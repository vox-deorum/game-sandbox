# Stage 8: Agent Communication

Status: done (all seven subplans complete: the Spades environment, template, and renderer; the harness chat routing with the signaler and daredevil examples; the relay visibility rules with the season messaging override; the chat panel for live sessions and replays; and the cross-cutting testing/CI/docs companion — the Docker-gated Spades chat integration tests in the `backend-integration` lane, the `spades.spec.ts` browser journey and season in `e2e.yml`, and the spec and docs reconciliation, all green)

## Goal

Agents and human-controlled slots can exchange messages during a session. The chat panel shows them live, and they appear in recordings and replays. Everything is optional. Agents without the hook and environments without the flag behave exactly as before. The test bed is **Spades, a new four-player partnership trick-taking environment built in this stage**: seats across the table are partners, so a targeted signal to your partner and a broadcast warning to the table are structurally different acts, which is exactly the distinction the visibility rules exist for. Hearts ships unchanged with messaging disabled, and so does Flappy Bird.

The stage builds in two halves, and every step ends with something you can put hands on. Steps 1 through 3 build Spades completely, locally playable, browser playable, replayable, and seasonable, before any communication work begins. Steps 4 through 6 then land messaging on top of a finished game: the harness hook with chatting examples you can run locally, the relay visibility rules and season override that make live chat safe before it ever reaches a screen, and the chat panel that turns the two-browser-window demo fully visual.

## Scope

Build **Spades** as the stage's product content. Standard single-hand rules: four seats in two partnerships (0 and 2 against 1 and 3), a bidding round from 0 to 13 where 0 is nil, thirteen tricks with follow-suit and spades-not-led-until-broken, tricks won by the highest spade or the highest card of the led suit. Scoring is ten points per bid trick plus one per bag on a made contract and minus ten per bid trick on a failed one; a nil bidder separately earns or loses one hundred, and a set nil's tricks count as tricks for the partner under the normal contract and bag rules (blind nil is not offered); the ten-bag penalty is omitted as meaningless in a single hand. One hand per episode, matching Hearts. Everything Stage 7 built is reused rather than reworked: the unpaced multi-slot loop, the multi-submission session images, the seat flows, and the seat-ordered scheduler (`seat_order_matters=true`, since partnership assignment and lead position both depend on the seat). Spades reports display scores (per-seat bids and tricks plus team totals) and a raw team score per seat as its higher-is-better leaderboard score, identical for both partners, following Hearts' raw-score precedent. It gets the full participant surface: a hand-authored `environments/spades/template/` layer, colocated examples, a built-in Naive agent, a student docs page, a browser renderer with on-screen bidding and card play, and season integration whose only backend change is registering the Spades forfeit floor, so a crashed or overrunning seat can never outrank honest play.

Implement chat routing in the harness per [communication.md](../docs/specs/communication.md). Immediately after `act` and before the environment applies the action, call `chat(inbox)` on agents that define it, passing the messages addressed to that slot since its last turn, each carrying its sender and tick; the agent chats knowing its chosen action but not the step's outcome. Enforce the rules in the harness at a single validation point: at most one message per recipient plus one broadcast per turn; plain text with length capped in Unicode code points by the environment metadata or the season override, whichever is lower; and messaging skipped entirely (byte-identical to today) when the environment or the config disables it. A message sent on tick T reaches its recipient's inbox on the recipient's next turn, strictly after T. Time spent in `chat` counts against the same per-step and per-episode limits as `act` and `learn`, extending the Stage 2 timing machinery with an additive `chat_ms` field that the season boards' efficiency aggregation also counts.

Messages flow into the per-step state object, carrying sender slot, recipient, text, and tick via placement. These schema fields have existed since Stage 1, so recording and replay need no format change. Apply the visibility rules at the relay, which learns which slots are genuinely human-bound (`externalSlots`, from the resolved slot assignment rather than the metadata's human-capable list). The backend forwards broadcasts to every connected client. It forwards a targeted message to the client controlling the addressed slot, and it reflects the controller's own sends back, so the panel renders them from the recorded truth with no local echo. It withholds other targeted messages from spectators during live play, including late attachers. Recordings keep every message, so replays show them all. Live chat history is best-effort from attach onward: a reconnecting client resumes from the current line, deduplicates the replayed latest state, and finds anything it missed in the replay. The effective messaging rules, enabled and cap, are resolved once at session start from the metadata and the season override, carried identically to the container, the relay, and the browser, and persisted on the session row, so a directly reopened ended session shows the same rules and hydrates its chat history from the recording.

Wire the human side per [interaction.md](../docs/specs/interaction.md). Outgoing messages from human-controlled slots travel the session WebSocket like input, but into a per-slot FIFO queue rather than the coalescing input latch, drained once per stepped tick. Build the chat panel as shared host chrome beside the decision log, not renderer content, so any future messaging environment gets it free: it shows broadcasts and messages addressed to slots controlled by the connected user, with a recipient selector, a cap counter, and an input box when that user controls a slot. Show recorded messages in the replay viewer at their ticks.

Activate the season messaging override that Stage 6 left inert: `overrides.messaging` becomes a real strict codec, the workflow runner spreads it into the session config like the timeout overrides, and, by owner decision, the orchestrator applies the play-open season's overrides, messaging and timeouts both, to live sessions as well, so a season's rules hold everywhere its agents run. The harness combines defensively (metadata AND config; minimum cap), so an override can silence or tighten but never enable messaging on an environment that opted out. The admin console's season editor replaces its Stage 8 placeholder with real messaging fields, so operators flip the toggle where they already edit the timeout overrides.

The examples make the messaging matter: a chat-less honest bidder proving the hook is optional, a signaler whose play provably depends on a partner's targeted message, and a daredevil that bids nil, broadcasts a warning, and gets covered by its partner. Verify the template's `chat` stub against the real harness through the interface-parity test.

3. **[Spades renderer and on-screen input](stage-08/3-spades-renderer-and-onscreen-input.md).** The `spades` browser renderer with bid chips and click-to-play greyed from the emitted mask, badges, team scores, replay, tie-aware web standings, and the registered Spades forfeit floor. 4. **[Harness chat routing and chatting examples](stage-08/4-harness-chat-and-chatting-examples.md).** The message router and single validation point, the `act → chat → step → learn` loop integration with next-turn delivery, `chat_ms` in the budgets, the bounded human FIFO queue in `live_io`, the defensive config combination, and the signaler and daredevil examples plus the template chat stub and its parity verification. Docker-free Python. Hands-on: run the daredevil hand locally and watch the partner cover a broadcast nil warning, with the exchange in the recording.
5. **[Relay visibility and the season messaging override](stage-08/5-relay-visibility-and-season-override.md).** The pinned `chat` command protocol with a shared code-point counter, audience-aware forwarding with `externalSlots`, sender reflection, the filtered late-attach stash, the full inbound authorization matrix, the effective messaging config resolved once, persisted on the session row, and carried to the container, the relay, and the browser, the `chat_ms` efficiency aggregation, and the activated season override applied by the workflow runner and now also by the orchestrator for live sessions, editable in the admin console. Docker-free backend. Hands-on: the two-window demo read from the browser's WebSocket frames, and the admin-console season toggle silencing live agents.
6. **[Chat panel, live and replay](stage-08/6-chat-panel-live-and-replay.md).** The `ChatPanel` host chrome on the session and replay pages, reconnect-safe accumulation through the jitter buffer, best-effort live history with the replay as the archive, ended-session hydration from the recording, and the send path over the already-pinned protocol with no local echo. Docker-free frontend. Hands-on: the two-window demo goes fully visual; watch the exchange scroll, scrub it in replay, and send a message an agent answers.
7. **[Testing, CI, and docs](stage-08/7-testing-ci-and-docs.md).** The whole-stage journey, the Docker-gated integration tests in the existing lane, the `spades.spec.ts` browser journey in `e2e.yml`, and the spec and docs reconciliation. Per-step tests live in each subplan.

## Done when

Spades itself is complete: a student can play a bid-and-thirteen-tricks hand locally through the template and in the browser with bids and cards both masked by the environment's legality, and a Spades season through the seat-ordered scheduler produces boards where partners share the raw team score, tied partners share a medal on the game-over standings, and a forfeited seat scores the registered Spades floor rather than above honest play.

In a Spades session: an agent broadcast appears on every connected panel, spectator pages included, with the frame of the tick it was sent, and lands in each other seat's inbox on that seat's next turn; a targeted message to a human-controlled slot is shown live only to the client controlling that slot, while the controller also sees their own sends reflected; the human's reply arrives in the agent's inbox the following turn; an over-cap message is rejected by the harness with the rest of the exchange intact; and the full exchange, targeted messages included, is visible in the replay. A reconnecting chat panel never duplicates a message and resumes from the current line, with the replay as the archive for anything missed, and a directly reopened ended session shows the full exchange from its recording. Disabling messaging at the season level silences the same agents without code changes, on scheduled workflow games and on live sessions both, now that the orchestrator applies the play-open season's overrides. Hearts and Flappy Bird recordings remain byte-identical to before the stage.
