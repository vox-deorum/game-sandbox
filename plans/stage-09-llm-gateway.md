# Stage 9: LLM Gateway

Status: not started (build order planned under [stage-09/](stage-09/)).

## Goal

Agents can call an OpenAI-compatible LLM API from inside the sandbox using the stock `openai` client. Every call is metered and logged. Budgets bound the bill. Owners can inspect their agents' prompts, while the public sees only usage metadata.

## Scope

Deploy the gateway per [llm.md](../docs/specs/llm.md). The stage-start evaluation the earlier draft asked for is done, and it split the gateway in two: LiteLLM's virtual keys meter in dollars rather than the spec's tokens and calls and require adding Postgres to a one-SQLite-file deployment, so the metering layer — key auth, token/call/rate budgets, the model allowlist, telemetry capture — is a **thin service embedded in the backend process** (`backend/src/gateway/`, its own Fastify listener on a dedicated port), where session, season, and run state already live. **LiteLLM survives as the default upstream**: a DB-less router configured under `gateway/` that translates OpenAI-shaped requests to whichever provider the deployment configures; a deployment may equally point the upstream URL straight at one OpenAI-compatible provider and skip it. The TypeScript-outside-rule exception in [execution.md](../docs/specs/execution.md) now covers only that upstream router. Streaming (`stream=true`) is rejected with a clear API error in this stage: turn-based agents gain nothing from it, and it keeps forwarding and usage extraction trivial. Budget exhaustion answers a non-retryable 400 (`budget_exceeded`) the agent can catch; rate limiting answers 429.

Enablement is **season-controlled only**. The never-consumed `EnvironmentMeta.llm` flag is removed, and the inert `overrides.llm` season block from Stage 6 becomes a strict codec: enabled (default false), a model list bounded by the deployment allowlist, budget and rate overrides. The play-open season's override governs live watch and play sessions exactly as the Stage 8 messaging override does; workflow runs read their frozen config snapshot; nothing turns on unless the deployment also configures an upstream.

Implement key issuance. When the orchestrator or workflow runner launches a container for an LLM-enabled session, it issues an in-memory one-off key per agent slot, scoped to that session and slot, carried to the harness in the session config argv. The harness sets `OPENAI_BASE_URL` once and swaps the acting slot's `OPENAI_API_KEY` around load, reset, and the per-tick hooks, so ordinary use of the stock `openai` client is attributed correctly even though agents run sequentially in one Python process. These slot keys are telemetry and budget attribution, not a security boundary between agents in one container — that remains the accepted class-scale tradeoff in [execution.md](../docs/specs/execution.md). Every key is revoked at the teardown convergence points when the container exits, and immediately when a launch fails after issuance. LLM sessions attach to a **per-session internal Docker network** whose single reachable endpoint is a dual-homed relay container forwarding to the backend's gateway port (via `host.docker.internal:host-gateway`, so Docker Desktop development and Linux CI behave identically); the future Kubernetes driver expresses the same profile as a network policy. Sessions without LLM keep no network at all.

Capture telemetry for every call, failures included: session, slot (from the key), model, full prompt and completion (truncation-capped), input, reasoning, and output token counts, and latency. Tick attribution uses a **marker**: before running the acting slot, the harness posts the current tick to the gateway's internal endpoint, and rows are stamped per key by arrival order — exact under sequential stepping, isolated per slot, and immune to both `PausableClock` drift and Docker Desktop VM clock skew, which rule out a timestamp join. At finalize the backend writes the rows as the `llm-telemetry` sidecar (`llm.jsonl`) beside the session's recording, declared in the header under the same schema version, per [recording.md](../docs/specs/recording.md).

Enforce budgets and limits at the gateway's admission gate, which reserves an estimated cost per call — read tokens from the request size, write tokens at the request's `max_tokens` or a quarter of the read estimate — and reconciles counters to actual upstream usage afterward, so one final call cannot blow far past an exhausted budget: token and call budgets **per slot per session** and **per submission per leaderboard run** (so one hungry agent starves neither its opponents in a match nor its competitors in a run), plus a per-key rate limit. All have deployment defaults and Stage 6 season overrides. An over-budget call fails with an ordinary catchable API error, the run continues, and budget exhaustion is never a forfeit.

Surface it. The replay viewer shows per-tick model, token, and latency metadata wherever the replay is public, fed by a server-side endpoint that masks prompt bodies per slot: only the slot's owner and operators receive them, and the owner's debug view on the agent profile is where they are read. The automated board shows aggregated token usage per model as a column next to timing, flowing from the gateway's authoritative per-model counters through `game_results` to the board and persisted placements, with the sidecar rows as the audit trail beside them. Wall-clock time waiting on the model already counts against the step limits through the harness timing; the stage pins that with a test rather than new machinery.

## Build order

Each step is its own subplan under [stage-09/](stage-09/), plus the cross-cutting [testing, CI, and docs](stage-09/7-testing-ci-and-docs.md) companion. The gateway lands first and Docker-free, the orchestration and network second, and every step ends with something you can put hands on.

1. **[The metering gateway and the LiteLLM upstream](stage-09/1-metering-gateway-and-upstream.md).** The backend-embedded gateway listener: slot-key auth, model allowlist, rate limit, per-key token/call budgets with the pinned OpenAI-shaped error contract, streaming rejection, forwarding to any OpenAI-compatible upstream, per-call telemetry capture, the `gateway/` LiteLLM config, and the operator's scratch-key diagnostic route. Docker-free against a stub upstream. Hands-on: curl the gateway with an issued key; watch the same key die at its budget.
2. **[Season enablement, slot keys, and the internal network](stage-09/2-enablement-keys-and-network.md).** The strict `overrides.llm` codec and admin editor fields, `resolveLlm` on both launch paths, removal of the dead `EnvironmentMeta.llm` flag, per-slot key issuance in the session config and revocation at teardown, and the `'llm'` sandbox network: a per-session internal network reaching only the gateway relay. Hands-on: from inside a container the gateway answers and the internet does not; the key stops working after exit.
3. **[Harness credentials and the template LLM example](stage-09/3-harness-credentials-and-template-example.md).** The per-slot credential swap around load, reset, and the tick hooks, byte-identical when disabled; the wall-clock timing pin; the `OPENAI_MODEL`-parameterized template example with a `python -m sandbox llm` command; the `examples/hearts/oracle` agent whose fallback demonstrates the catchable-error contract; and the student LLM guide. Hands-on: the same code runs locally on the class key and in a session against the gateway.
4. **[The telemetry sidecar](stage-09/4-telemetry-sidecar.md).** The `llm-telemetry` schema and generated types with golden fixtures, the header declaration, the tick-attribution marker, and the finalize-time write of `llm.jsonl` beside the recording in both launch paths, retention included. Hands-on: open a recording directory and read the schema-valid call log keyed by tick and slot.
5. **[Run budgets and token aggregation](stage-09/5-run-budgets-and-token-aggregation.md).** Per-submission-per-run counters at the gateway spanning a run's sessions, workflow-runner run scope, token-by-model totals through `game_results` into the automated board and persisted placements, the pinned over-budget-but-honest journey, and the llm.md budget semantics. Hands-on: a tiny-budget season run where exhaustion is caught, finished, and visible in the board's numbers.
6. **[Replay metadata, the owner debug view, and board tokens](stage-09/6-frontend-surfacing.md).** The per-slot-masked sidecar endpoint, the public per-tick Model-calls panel in the replay viewer, the owner/operator prompt browser replacing the Stage 5 profile placeholder, and the token column on the automated board. Hands-on: the whole visibility story in a browser.
7. **[Testing, CI, and docs](stage-09/7-testing-ci-and-docs.md).** The whole-stage integration journey and byte-identical regression gates in the Docker lane, the `llm.spec.ts` browser journey, the optional LiteLLM config smoke, and the spec, configuration, and student-docs reconciliation sweep.

## Done when

The template repo's LLM example runs unmodified in both places: locally with the class key in `.env`, and inside a session against the gateway. From inside a container, the gateway answers and the open internet does not. A replayed session shows per-tick call metadata attributed to the correct slot, with prompts visible only to the owner and operators, and the board shows token usage per model. A test agent that exceeds its session or run budget receives a catchable API error and finishes its episode without forfeiting. A revoked slot key stops authorizing after the container exits, and sessions of seasons that never enabled the capability remain byte-identical to today.
